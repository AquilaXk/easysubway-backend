쉬운 지하철 개인정보처리방침

개정 공고일: 2026년 8월 13일 · 시행일: 2026년 8월 20일

쉬운 지하철(easysubway)은 교통약자가 도시철도를 더 쉽게 이용할 수 있도록 역, 시설, 경로, 신고 기능을 제공합니다. 이 문서는 앱에서 처리하는 개인정보, 보관 기준, 삭제 요청 방법, 문의 창구를 설명합니다.

1. 개인정보 처리방침의 적용

이 방침은 아퀼라 소프트웨어가 운영하는 쉬운 지하철 앱과 연결된 백엔드 기능에 적용됩니다. 외부 지도와 공공데이터 제공처 등 다른 사업자의 서비스에는 해당 사업자의 방침이 적용됩니다.

2. 처리하는 개인정보 항목과 목적

3. 개인정보를 처리하는 방법

앱 설정과 최근 검색처럼 기기 안에서 처리하는 정보는 이용자의 기기에 저장됩니다. 시설 신고 제출, Journey V3 서버 경로 검색, 선택형 ITX-청춘 경로 검색, 데이터 삭제 요청처럼 네트워크가 필요한 기능은 이용자가 해당 기능을 실행할 때 HTTPS로 전송됩니다.

4. Journey V3 서버 경로 검색

배포 환경의 정본 지하철 경로 검색은 Journey V3 서버에서 수행합니다. 앱은 requestId, 출발·도착역 ID, 즉시 또는 예약 출발 기준, timetable 또는 realtime 정책, mobility profile, constraint mode, 최대 환승 수와 대안 수를 HTTPS 요청으로 보냅니다. 서버는 검증된 active route-bundle과 RAPTOR로 경로를 계산하며 필요한 데이터나 실시간 정보가 없거나 만료·불일치하면 이전·로컬 경로로 대체하지 않습니다.

Journey V3 요청 본문과 계산 결과는 요청 처리 중에만 사용하며 별도 검색 이력으로 저장하지 않습니다. 응답에는 private, no-store cache 정책을 적용하고 request를 사용자·기기·계정 ID와 연결하지 않습니다.

Journey V3 또는 기존 Route V2 경로 세션을 만들 때 앱은 Google Play Integrity에 requestHash를 보내고, Google은 무결성 확인을 위해 앱 package·version·certificate, 단말에서 로그인된 Google Play 계정의 license 상태와 기기 attestation 정보를 암호화해 처리합니다. 이 정보는 Google의 Play Integrity 고정 보관 정책을 따르며 Google이 제3자에게 전송하지 않습니다. 그 뒤 앱은 integrityToken과 128-bit clientNonce를 쉬운 지하철 backend로 전송하고, backend는 검증을 위해 raw integrityToken을 Google Play Integrity decode API로 전송합니다. 쉬운 지하철 backend의 경로 세션·상태는 사용자·기기·계정 ID와 연결하지 않지만, 위 Google 처리 범위는 이 backend 비연결 경계와 구분됩니다.

Journey V3 backend는 raw integrityToken, raw nonce와 raw bearer token을 저장하지 않습니다. 검증 후 token SHA-256, journey:v3 scope, issuedAt, expiresAt, requestCount를 논리적으로 10분 동안, nonce SHA-256, claimedAt, expiresAt을 논리적으로 2분 동안 저장합니다. 만료된 Journey V3 행은 이후 새 세션 발급 시 같은 transaction의 cleanup 단계에서 물리 삭제하며 별도 고정 주기 purge를 사용하지 않습니다.

기존 Route V2 backend도 raw integrityToken을 저장하지 않고, 검증 후 발급한 세션 token의 SHA-256, scope, issuedAt, expiresAt, requestCount를 논리적으로 10분 동안, raw nonce 대신 nonce SHA-256을 논리적으로 2분 동안 저장합니다. 정상 동작 중 Route V2 만료 데이터는 기본 5분 주기 purge로 물리 삭제하므로 세션은 발급 후 약 15분 이내, nonce 해시는 수신 후 약 7분 이내 삭제됩니다. ITX 경로 요청의 실제 JSON에는 originStationId, destinationStationId, departureTime, mobilityType, mobilityPreset, constraintMode, useRealtime, maxTransfers, alternativeCount가 포함됩니다.

경로 상태 DB에는 routeStateId, 출발역·도착역 ID, backend가 정한 transport scope, 요청 출발 시각, 계산된 itinerary JSON, timetable artifact ID, createdAt, plannedArrivalAt, expiresAt을 저장합니다. mobilityPreset은 itinerary JSON의 보행 구간 appliedPreset에도 포함되므로 이 이동 조건 처리는 ephemeral로 표시하지 않습니다. 논리 보관 기간은 min(createdAt+6h, max(createdAt+30m, plannedArrivalAt+30m))로 생성 시각부터 최소 30분, 최대 6시간이며, 정상 동작 중 물리 삭제는 expiresAt 뒤 5분 이내입니다.

backend는 Route V2와 Journey V3의 raw integrityToken, raw nonce, Integrity payload·verdict를 DB에 저장하거나 로그에 남기지 않으며, Journey V3 요청·응답을 별도 검색 이력으로 저장하지 않습니다. Route V2는 raw 검색어와 좌표를 요청으로 보내거나 저장하지 않습니다. 별도로 gateway는 요청 제한을 위해 IP의 이진 표현인 $binary_remote_addr와 Bearer 세션 token이 든 $http_authorization을 Nginx shared memory key로 처리합니다. 이 상태는 요청이 끝난 뒤에도 shared memory에 남을 수 있어 ephemeral 처리로 분류하지 않습니다. 고정 TTL은 없으며, zone 메모리가 부족할 때 LRU 방식으로 퇴출되고 최종적으로 gateway process 또는 shared-memory zone 수명 종료 시 삭제됩니다. 설정의 10m은 보관 기간이 아니라 zone 용량입니다. 이 key 값은 DB나 access log에는 저장하지 않습니다. 제한 응답 로그에는 고정 event·scope·status만 남고 key 값은 포함하지 않습니다. 세션과 경로 응답에는 private, no-store cache 정책을 적용합니다.

5. 민감한 상태 정보

쉬운 지하철은 장애, 임신, 질병, 부상 여부를 증명하는 서류나 진단정보를 요구하지 않습니다. 앱은 사용자가 직접 선택한 이동 조건을 경로 안내에만 사용하며, 광고나 추적 목적으로 사용하지 않습니다.

6. 보관, 전송 및 파기

즐겨찾기, 최근 검색, 앱 설정, 신고 초안, 설치된 이동 정보 기록은 기본적으로 사용자 기기에 보관됩니다. 신고 제출, Journey V3 서버 경로 검색, 선택형 ITX-청춘 경로 검색, 삭제 요청처럼 네트워크 전송이 필요한 경우 HTTPS를 사용합니다. 보관 목적이 끝나거나 삭제 요청 처리가 완료된 개인정보는 복구하기 어렵게 삭제하거나 식별 가능성을 줄입니다.

시설 신고의 사용자 연결, 신고 본문, 원본·썸네일 사진, 위치 좌표와 제출 식별값은 접수일부터 최대 1년 보관합니다. 운영 서버는 매일 보관 상한이 지난 신고를 확인해 해당 개인정보를 자동 삭제 또는 익명화하고, 역·시설·신고 유형·처리 상태처럼 개인을 식별하지 않는 운영 이력만 남깁니다. 이용자가 그 전에 데이터 삭제를 요청하면 확인 후 같은 항목을 지체 없이 처리합니다.

장애 복구를 위해 만든 제한된 PostgreSQL 백업 사본은 백업 생성일부터 최대 30일 보관하며, 백업 생성 시와 운영 환경의 일일 자동 작업에서 만료 사본을 삭제합니다. 데이터 삭제 요청 후에도 이미 생성된 백업 사본은 이 기간 안에서 장애 복구 목적으로만 제한하여 보관될 수 있습니다. 운영 객체 스토리지의 신고 사진은 별도 백업 사본을 만들지 않으며 운영 object의 보관·파기 기준을 그대로 적용합니다.

7. 제3자 제공, 처리 위탁 및 추적

쉬운 지하철은 개인정보나 민감정보를 판매하지 않습니다. 광고 목적의 tracking을 하지 않으며, 신고 사진과 위치 정보는 앱 기능 제공과 신고 검토 목적에만 사용합니다. 출구 정보가 표시되면 카카오맵 미리보기를 자동으로 불러오며 공개 역·출구 좌표와 지도 화면 범위를 카카오에 전달하지만 현재 위치는 사용하지 않습니다. 사용자가 화면의 전달 안내를 확인하고 출구 도보 길안내를 명시적으로 누르면 카카오맵 앱에는 현재 위치 시작 좌표와 목적지 좌표를, 카카오맵 웹에는 목적지 좌표를 전달합니다. 이 좌표는 쉬운 지하철 서버에 저장하지 않습니다. 서비스 운영에 필요한 범위에서만 Cloudflare, Oracle Cloud Infrastructure, Google Play Console 같은 인프라와 스토어 운영 도구를 사용할 수 있으며, 이 경우 해당 사업자는 서비스 제공, 보안, 저장, 배포, 진단 목적의 처리만 수행합니다.

8. 개인위치정보의 처리

가까운 역 찾기에 사용하는 현재 위치는 기기에서만 처리합니다. 시설 신고에 위치를 선택해 첨부하면 운영자 서버에 전송되어 제2항과 제6항의 기준으로 처리됩니다. 출구 도보 길안내를 누르면 카카오맵 앱에는 현재 위치와 목적지 좌표가, 카카오맵 웹에는 목적지 좌표만 전달됩니다. 자세한 내용과 이용자의 권리는 위치정보 이용약관에서 확인할 수 있습니다.

9. 이용자 및 법정대리인의 권리

사용자는 개인정보 열람, 정정, 삭제, 처리 정지를 요청할 수 있습니다. 신고 데이터 삭제, 개인정보 문의, 보안 신고는 아래 주소로 요청할 수 있으며, 요청 확인에 필요한 최소 정보만 확인한 뒤 처리합니다.

10. 안전성 확보 조치와 자동 처리 정보

개인정보는 접근 권한을 제한하고, 운영 로그에는 신고 receipt token, 사진 원본, 서명된 업로드 URL, 저장소 자격 증명을 남기지 않도록 관리합니다. 관리자 화면은 인증된 운영자만 접근할 수 있으며, 네트워크 전송에는 HTTPS를 사용합니다.

웹 기반 운영 경계에서는 보안과 요청 제한을 위해 IP 주소가 메모리 키로 처리될 수 있으나 DB 또는 access log에 저장하지 않습니다. 쉬운 지하철은 맞춤형 광고를 위한 쿠키나 행태정보 추적 도구를 사용하지 않습니다.
