릴리스 요청

게시 대상 후보를 골라 릴리스 요청을 생성하고, 다른 관리자가 승인합니다. 이 승인은 이력 기록이며 게시를 발화하지 않습니다 — 프로덕션 게이트는 아래 수동 dispatch로 실행합니다.

수동 dispatch 필요

승인된 요청은 아래 명령의 경로 표시를 실제 evidence 파일로 바꾼 뒤 실행합니다. 요청 행의 대상 채널에 맞는 명령을 사용합니다 — production-publish는 targetChannel=production에서만 허용되고 다른 채널로 보내면 워크플로가 즉시 실패합니다.

프로덕션 요청

gh workflow run datapack-release.yml \
  --ref main \
  -f mode=production-publish \
  -f targetChannel=production \
  -f modeArgs='{"buildSpecPath":"<빌드 스펙 경로>","releaseRequestId":"<릴리스 요청 ID>","releaseRequestPath":"<릴리스 요청 파일 경로>","androidEvidencePath":"<Android 증거 경로>","strictRouteRegressionPath":"<경로 회귀 증거 경로>"}'

스테이징 · 개발 요청

gh workflow run datapack-release.yml \
  --ref main \
  -f mode=exploratory \
  -f targetChannel=<staging 또는 dev> \
  -f modeArgs='{"buildSpecPath":"<빌드 스펙 경로>","releaseRequestId":"<릴리스 요청 ID>","allowGaps":"false"}'

후보 등록: 현재 후보 생성·등록 경로는 없습니다. 이 화면은 datapack_candidates에 이미 등록된 PROMOTED 행만 읽습니다. 등록되지 않은 후보를 추정하거나 DB에 직접 넣지 말고 릴리스 요청 생성을 중단합니다.
